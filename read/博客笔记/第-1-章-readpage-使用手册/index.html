ReadPage 使用手册 ​

把 Obsidian 笔记变成「微信读书」：电脑端在 Obsidian 里维护笔记与书结构，手机浏览器像阅读 App 一样读书。免费、纯静态、无后端。

1. ReadPage 是什么 ​

ReadPage 是一套把 Obsidian 知识库组织成「书架 → 书 → 章节」 的阅读站工具：

  • 内容不动：笔记仍然在 Obsidian 里编辑、双链、维护，是唯一的「内容来源」；
  • 新增一层阅读组织：把若干篇笔记编成「一本书」（带步骤/章节目录），若干本书组成「书架」；
  • 生成一个静态阅读站：手机浏览器打开，体验接近微信读书——书架封面格子、沉浸式阅读、翻页模式、阅读进度、章末自动标记、书内搜索。

技术栈：VitePress 静态站 + Python 同步脚本，部署到 GitHub Pages 或任意静态托管，全程免费、无后端、无数据库。

2. 效果一览 ​

2.1 书架页：像真实书架 ​

  • 多书架切换（下拉选择，记忆上次选择）+ 书名搜索；
  • 书以封面格子展示（有封面图显示图片，没有则用色块 + 书名）；
  • 书架内按最近阅读排序：最近读过的书自动排前面，书脊/封面显示「今天」「3 天前」等阅读痕迹；
  • 书状态自动推导：在读 / 想读 / 读完 / 搁置——读完的书灰显 + ✓，搁置的书半透明。

2.2 阅读页：沉浸式阅读 ​

  • 沉浸模式：进入章节后顶部/底部栏自动收起，正文全屏；点击屏幕唤出菜单，3 秒无操作自动隐藏；
  • 三种阅读方式：上下滚动（默认）、上下翻页、左右翻页（设置里切换，翻页模式显示页码）；
  • 阅读设置：字号、行距、字体、深浅主题（内置 6 套主题：浅色 / 深色 / 护眼 / 夜读 / GitHub / Notion 风）；
  • 图片查看：点击正文图片全屏预览，可放大 3 倍并拖动查看细节；
  • 章末自动完成：滚动/翻页到章节末尾，自动标记本章已读（最后一章显示「本书已读完」）。

2.3 阅读工具：目录 / 大纲 / 搜索 ​

  • 📑 目录：全书步/章列表（当前章高亮、已读打 ✓），含「大纲」标签页展示全书大纲树（步 → 章 → 小节，点击直达）；
  • 🔍 搜索：书内搜索章标题与小节标题，跨章跳转；
  • 📋 大纲：本章小节列表，点击平滑滚动定位；
  • ⚙ 设置：字号 / 行距 / 翻页方式 / 主题 / 沉浸开关。

2.4 进度与状态：全自动 ​

  • 阅读进度、已读章节、阅读位置全部存在浏览器本地（localStorage），无需登录；
  • 「读完」由「全部必读章节已勾选」自动推导，不需要手动维护任何状态；
  • 选读章节（#选读）不计入「读完」判定。

3. 核心概念：三个角色 ​

角色是什么谁维护
笔记知识库里的 Markdown 文件，内容的唯一来源Obsidian（照常编辑）
书文件一个 Markdown 文件 = 一本书：frontmatter 声明书架归属，正文是「步 → 章 → 笔记链接」的目录手动（薄文件，成本低）
书架由书文件的 bookshelf 属性自动聚合出的分组无需维护（派生视图）

关键设计：书不复制内容，只引用笔记（[笔记名]()）。笔记留在知识库，书只是「按什么顺序读它们」的记录——建书成本极低，改书不影响内容，内容更新自动反映到阅读站。

4. 五分钟上手 ​

4.1 环境准备 ​

  • Python 3.x
  • Node.js ≥ 22
  • pnpm（npm install -g pnpm）

4.2 获取项目 ​

把 readpage/ 目录复制到你的仓库（或 Obsidian vault 根目录）下：

readpage/
├── books/                # 书文件（也可放在知识库任意目录，按属性识别）
├── scripts/
│   ├── sync.py           # 同步脚本：书驱动，只同步书引用的笔记
│   └── commit.ps1        # 一键 同步 + 提交 + 推送
├── .vitepress/           # VitePress 配置与阅读主题
└── package.json

安装依赖：pnpm install（在 readpage/ 下）。

4.3 写第一本书 ​

在 readpage/books/ 新建一个 Markdown 文件（或放在知识库任意目录，见 5.1）：

markdown
---
title: 我的第一本书
bookshelf: 入门书架
---
# 第一步 开始
## 第 1 章 认识笔记
- [[我的第一篇笔记]]
# 后记
- [[学习总结]]
  • bookshelf：书归属的书架名（不写 = 不进书架）；
  • # 第几步 / ## 第几章：目录层级，最多两级；
  • - [笔记名]()：章节指向知识库里的笔记（任意位置，按文件名查找）；
  • # 后记：书的收尾章节（可选）。

4.4 同步与本地预览 ​

bash
cd readpage
python3 scripts/sync.py     # 同步：扫描书 → 收集引用 → 同步笔记 → 生成数据与页面
pnpm docs:dev               # 本地预览 http://localhost:5173（--host 可局域网/手机访问）

手机预览：pnpm docs:dev 后终端会显示 Network: http://192.168.x.x:5173/，手机连同一 WiFi 访问（首次需在 Windows 防火墙允许 Node.js）。

4.5 部署上线（GitHub Pages） ​

  1. 在 GitHub 建一个仓库（如 yourname/readpage）；
  2. 在项目根加一个 workflow（.github/workflows/deploy-readpage.yml），参考：
yaml
name: 部署 readpage 阅读站
on:
  push:
    branches: [master]
    paths:
      - 'layer_id_files/**'   # 笔记内容变更（按你的目录改）
      - 'readpage/**'         # 工具/书文件变更
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.x" }
      - uses: actions/setup-node@v4
        with: { node-version: "22" }
      - run: npm install -g pnpm
      - name: 安装依赖
        working-directory: readpage
        run: pnpm install
      - name: 同步
        working-directory: readpage
        run: python3 scripts/sync.py
      - name: 构建
        working-directory: readpage
        run: npx vitepress build
      - name: 部署
        uses: JamesIves/github-pages-deploy-action@v4
        with:
          token: ${<!-- -->{ secrets.ACTION_TOKEN }}
          repository-name: yourname/readpage
          branch: gh-pages
          folder: readpage/.vitepress/dist
  1. 推送后访问 https://yourname.github.io/readpage/（在仓库 Settings → Pages 确认路径）。

电脑端日常更新：./scripts/commit.ps1（同步 → 提交 → 推送，CI 自动重建部署）。

5. 书文件格式参考 ​

5.1 frontmatter 字段 ​

字段必填取值说明
title✅文本书名
bookshelf✅文本归属书架；不写 = 不进书架
shelved❌true / falsefalse = 显式不上架（文件仍在，只是书架不显示）
status❌想读 / 搁置结构性状态；在读/读完由阅读自动推导，勿手写
shelf_order❌数字书架内排序（未读过时生效）
cover❌图片 URL封面图；不写则用色块 + 书名（也兼容 banner_img）

💡 书文件不需要放在 readpage/books/：放在知识库任意目录（和普通笔记混放）也可以，只要 frontmatter 有 bookshelf 字段就会被识别。

5.2 正文结构 ​

# 第几步           ← 阶段（一级目录）
## 第几章          ← 章节（二级目录，一本书最多两级）
- [[笔记名]]       ← 章节内容：引用知识库笔记
  • 一章可以引用多篇笔记（正文按顺序拼接阅读）；
  • 结构手动维护（这是设计取舍：自动维护成本高且容易失控，手动维护一本书的成本约等于写一个目录）。

5.3 章节属性与特殊写法 ​

写法含义
- [笔记]()正常章节
- [笔记]() #重点重点章节（列表加标记）
- [笔记]() #选读选读章节（不计入「读完」判定）
- [笔记]() #隐藏隐藏章节（目录/大纲不出现）
- 纯文字（无链接）占位章节（灰色、不可点击，用于「待整理」）

后记：单独一个 # 后记 步，下面放 - [后记笔记]()（可以不写章标题）。

5.4 完整示例 ​

markdown
---
title: Java 并发从入门到面试
bookshelf: Java 基础
shelved: true
status: 想读
shelf_order: 1
---
# 第一步 理解线程
## 第 1 章 线程的创建
- [[Java并发编程_基础概念]]
## 第 2 章 线程池
- [[Java并发编程_线程池]] #重点
- [[CompletableFuture方法使用]] #选读
# 第二步 并发工具
## 第 3 章 待整理
- 第 3 章内容还没整理
# 后记
- [[并发学习总结]]

6. 同步脚本说明 ​

sync.py 是书驱动的：先扫描书文件 → 收集书引用的笔记 → 在知识库任意位置查找 → 只同步被引用的笔记。因此：

  • 笔记放在哪里都行（1.5、1.7、2.x…），书引用到就会上线；
  • 没被任何书引用的笔记不会出现在阅读站（站点只有你规划要读的内容）；
  • 找不到的引用会在同步时警告列出（不中断构建）。

常用命令：

bash
python3 scripts/sync.py                    # 默认：books/ + 知识库全域找书，layer_id_files 找笔记
python3 scripts/sync.py --kb 你的知识库根   # 指定笔记搜索根
python3 scripts/sync.py --books 某个目录    # 追加书文件目录（可重复）
pnpm docs:build                            # 构建静态产物（.vitepress/dist）

7. 常见问题 ​

Q1：同步时提示「找不到笔记 xxx」？ 书里引用的笔记名在知识库中不存在（或不在 --kb 指定的根目录下）。检查笔记文件名是否一致（含空格、大小写）。

Q2：阅读进度换手机/换浏览器就没了？ 进度存在浏览器 localStorage（单设备），这是静态站的无后端设计。介意的话可以接受「主力设备阅读」模式，或后续加导出/导入进度 JSON。

Q3：手机上能写笔记/写后记吗？ 不能。静态站只有「读 + 进度」能力；写笔记、改书结构都在电脑端 Obsidian 完成，同步部署后手机自动更新。

Q4：一本书里最多几级目录？ 两级（第几步 → 第几章）。出现「章的章」说明该拆书了——拆书而不是加层级（层级是维护成本信号）。

Q5：书封面图从哪来？ 书文件 frontmatter 写 cover: https://...图片地址；不写就用色块 + 书名（色块颜色按书名自动生成）。

Q6：书结构能自动生成吗？ 可以半自动：按知识库目录的层级/排序，手动把 - [笔记]() 行拖进书文件即可（脚本提供稳定的解析，结构本身建议手动确认——这正是「聚焦内容处理」的设计意图）。

Q7：会不会把知识库改坏？ 不会。脚本只读知识库、只写 readpage/docs/；书文件是新增文件，不动任何原笔记。

8. 设计取舍与限制 ​

  • 静态无写回：手机端只读 + 本地进度，换来零成本、免维护、永远在线；
  • 进度单设备：localStorage 存储，清缓存会丢（可接受：阅读是单设备行为）；
  • 结构手动维护：自动整理会让人跳过内容（原项目的教训）——书目录是「阅读路径」而不是「内容容器」，维护成本极低；
  • 同步范围 = 书引用：站点内容由书决定，没进书的内容不上线，天然对抗「囤积」。
